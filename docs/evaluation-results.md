# Evaluation results

Snapshot of the 28 Oct run with all three models ([model-eval run](https://github.com/Johndenisnyagah/prompt-injection-guardrail/actions/runs/40675789307)). The window-size table is from the earlier [sweep run](https://github.com/Johndenisnyagah/prompt-injection-guardrail/actions/runs/40659610005), which compared the fine-tuned model and ProtectAI only. The workflow re-runs weekly and on every change to the inference path or the sets; its job summary always has the latest numbers.

Generated by `scripts/eval_models.py` on 2026-10-28 (GitHub runner, CPU, Python 3.12.15, torch 2.14.1+cpu, transformers 5.21.0). Threshold 0.5. All scoring goes through the API's own inference path, including long-input windowing.

## How to read this

- **Clean holdout (v3)** and **benign set** are the trustworthy numbers: neither influenced training or model selection.
- The **validation set** steered three rounds of development, so the fine-tuned model's score on it is optimistic. It is shown for comparison only.
- The **long-input** rows take each clean-holdout attack and place it after 702 tokens of harmless text. *Windowed* is how the API scans today; *first 512 tokens only* is how it scanned before the fix.
- Small denominators: read fractions, not percentages.

## What these results changed

- **Fine-tuning is what makes it work, at a price.** On the clean holdout the stock Prompt Guard 2 catches 9/60 and the fine-tuned model 58/60. With attacks hidden in long input: 2/60 vs 53/60. The price is false positives on the clean benign set: 1/100 for the base model, 8/100 after fine-tuning. On the v2 benign holdout, fine-tuning lowered them (11/60 → 7/60).

- **The long-input bypass was real on the real model.** Scanning only the first 512 tokens caught 0 of 60 padded attacks; windowed scanning catches 53. The remaining gap is dilution: the attack shares its window with a few hundred harmless tokens.
- **Window size stays at 512.** 256- and 128-token windows caught one more attack (54/60) at two to four times the inference cost, with no change in long-document false positives.
- **The false-positive rate is higher than the 53-prompt set suggested.** 0/26 there, but 8/100 on the clean benign set and 7/60 on the v2 holdout. Most errors are users instructing the assistant about its own output ("Answer only with code from now on", "Cancel the earlier instruction I gave you…"), the same confusion between the user's and the system's instructions that v2 targeted, in forms its templates did not cover.
- **Against ProtectAI's DeBERTa baseline**, the fine-tuned model trades two holdout misses (58/60 vs 60/60) for far fewer false positives (8/100 vs 17/100; 7/60 vs 38/60) and much better long-input recall (53/60 vs 30/60).
- **CPU cost matters for long inputs.** About 150 ms per short prompt on a CI runner, and about 15 s for a 20,000-character prompt (12 windows). On CPU, the input cap is also a denial-of-service limit.
